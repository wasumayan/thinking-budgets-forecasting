everything else was probed through the WebFetch tool, which cannot reach `wikimedia.org`, `en.wikipedia.org`

## 3. Recommendation: build **"FreshMM-26"** (working name) in ~1 day

### 3.1 Design
Four domains, ~160 series, two frequencies, three text types, everything keyless except (optionally) EIA.

| Domain | Series (count) | Source | Freq | T | H | stride | horizon starts ≥ 2025-08-01 (to 2026-09-05) | windows |
|---|---|---|---|---|---|---|---|---|
| **Web attention** | 60 English Wikipedia articles, 10 per topic cluster: Public health (Influenza, Measles, COVID-19, Mpox, RSV, Bird flu, …), Finance/Economy (Bitcoin, Inflation, Tariff, Federal Reserve, Recession, Unemployment, …), Energy (Gasoline, OPEC, Crude oil, Natural gas, Hurricane season…), Politics/Geopolitics (named elections/conflicts), Science/Tech (named launches, models), Sports/Entertainment (2026 FIFA World Cup, Super Bowl LX, named films). Totals: ~165 series, **~3,400 windows with horizon start ≥ 2025-08-01** (≈ 2,400 at daily stride 24); ≥ 400 windows with horizon start ≥ 2026-07-01 (post-cutoff for June-2026 models such as Fable 5.1). All four requirements met (≥300 windows, ≥50 series, ≥3 domains, ≥2 text types).

### 3.2 Text attached per window (strict `available_at <= origin`)
Every text item carries `available_at` (UTC date-time it became public). A window with history `[t_{o-95}, t_o]` (origin `o`) and horizon `[t_{o+1}, t_{o+H}]` may only include items with `available_at <= t_o` (for daily wiki data use end of day `t_o`; for weekly ILI the CDC report for epiweek `w` has `available_at = Friday of week w+1`, so it is visible only when `t_o >= that Friday`).
1. **metadata** (str, static): Wikipedia `summary.extract` / FRED `notes` / ILINet description ("Percentage of outpatient visits for influenza-like illness reported to ILINet, {region}") + units + frequency + "Prediction target period: {h_start} to {h_end}" (TimesX template).
2. **calendar** (str): `holidays.US()` holidays inside the horizon (TimesX template).
3. **events** (list, K ≤ 10, newest first, each `{"date","category","text","links"}`): Wikipedia Current-events bullets from the 28 days ending at `t_o`, selected by (a) any `[[wikilink]]` equal to the target article or in its cluster's keyword list (pageview series), or (b) category ∈ {Business and economy, Disasters and accidents, Health and environment, International relations} ∧ keyword match (`oil|OPEC|gasoline|hurricane|Fed|interest rate|tariff|inflation|influenza|measles|...`) for FRED/EIA/ILI series. Strip wiki markup, keep the citation-free sentence.
4. **reports** (list, ≤ 2 most recent): CDC FluView Key Points (health), EIA WPSR highlights paragraph(s) / WNGSR summary sentence (energy); none for FX (state `null`).
5. **covariates** (optional, str, TimesX style): summary stats of 1-3 related series over the history window (e.g., for gasoline: WTI, crude stocks), computed only from history → no leakage by construction.

Serialize as parquet with the `TimesXWindow`-style schema from verify-datasets.md plus `text_available_at_max` and assert `text_available_at_max <= origin_ts` in a unit test (leakage audit).

### 3.3 Build plan (one coding-agent day)
1. `series.yaml` (1 h): id, domain, source, fetch spec, title, units, freq, cluster keywords. Start from the lists above.
2. Numeric fetchers (2 h): `wikimedia_pageviews(title, start, end)` (1 call/series, JSON); `fred_csv(id)` (1 call/series); `delphi_fluview(regions, epiweeks)` (1 call for all regions via comma list); `delphi_covidcast(...)` (1 call/signal); optional `eia_v2(route, series)`. Cache raw JSON/CSV to disk with fetch timestamp.
3. Text fetchers (2 h): Current-events wikitext for 2025-06-01..today (≈ 460 calls, parse `;Category` + `*` bullets, extract `[[links]]`, drop `{{...}}`/refs); Wikipedia summaries (60 calls); CDC FluView pages `2025-week-30 … 2026-week-35` (≈ 60 calls; extract "Key Points" `<ul>`), WPSR highlights PDFs (≈ 60; `pdftotext`) — optional; FRED notes.
4. Windowing + attachment (1 h): rolling windows per series, `available_at` filter, K=10 events, parquet writer, leakage assertion.
5. Baselines + metric (1 h): seasonal naive (m=7 daily-wiki, m=1 business-day FRED, m=52 weekly), Chronos-2/TimesFM-2.5 zero-shot, LLM-with-text; report per-series MASE (in-sample seasonal scaling), `gmean(MASE/MASE_snaive)` and `fev.leaderboard(n_resamples=1000)`.
6. QA (1 h): plots of 20 random windows with attached text; count windows per cut (≥2025-08-01, ≥2026-01-01, ≥2026-07-01); check heavy tails (log1p for wiki), missing values (FRED `.`), ILI off-season near-zero text.

### 3.4 Known pitfalls
- **Revisions/backfill:** ILINet (and NSSP) values are revised for several weeks; FRED `ICSA` is revised once. Decide up front: evaluate against *final* values (simplest) and, if realism matters, build history from Delphi `issues=<origin epiweek>` vintages. FX, yields, oil, pageviews are not revised.
- **Cutoffs:** 2025-08-01 is safe for models with ≤ mid-2025 cutoffs; for June-2026 models use the ≥ 2026-07-01 subset (~400 windows) and keep the pipeline re-runnable monthly (the dataset is inherently refreshable — same argument TimesX makes).
- **Licensing of the release:** numbers: CC0 (Wikimedia), public domain (Fed, EIA, DOL, CDC); text: Wikipedia CC BY-SA 4.0 (→ dataset must be CC BY-SA), CDC/EIA public domain. Do not include NYT text or S&P/CBOE index levels.
- **Wikipedia titles:** use canonical titles (redirect-resolved, underscores, percent-encoded); watch for page moves/renames (pageviews are per title, not per page id) and for articles created after 2024 (short history).
- **Off-season health text** is nearly content-free from May-October; the interesting ILI windows start ~2025-11.
- **Google Trends is out**; do not budget time for it.

### 3.5 If more is needed later
- Cheap additional series: NSSP 3 signals x 51 states (+153 weekly); EIA state-level gasoline (~10); Wikipedia `top` lists for automatic article discovery; DBnomics for non-US macro.
- Richer events: NYT Archive (private use only) or GDELT `timelinevol` counts as a numeric covariate.
